03 case studies

01 / Backend architecture

ERP Management System

ERP records need access checks on every protected route. I built the authentication layer around Express middleware, with a shared path from request validation to PostgreSQL.

  • TypeScript
  • Node.js
  • Express.js
  • Prisma ORM
  • PostgreSQL
  • JWT
  • bcrypt
View repository
Engineering notes

REST authentication endpoints issue JWTs in HTTP-only cookies. Middleware checks the token on protected routes. bcrypt hashes passwords before storage.

Routes, validation and the Prisma schema live in separate modules. Changing what a route accepts leaves the data model independent.

02 / Real-time collaboration

CampusConnect

Students need a place to find teammates across campuses. CampusConnect brings profiles, team invitations, messages and shared files into one collaboration space.

  • JavaScript
  • Firebase
  • Firestore
  • Supabase
Visit CampusConnect
Engineering notes

The Firestore model follows users, teams, invitations and messages. Listeners update conversations and presence as students move in and out of a team.

Authentication ties profiles to members. Supabase stores shared files separately from the live message data.

03 / REST API design

Student Management System

A student records API with predictable create, read, update and delete operations. DTOs define the public contract, while soft deletion keeps a removed record recoverable.

  • Java
  • Spring Boot
  • Spring Data JPA
  • MySQL
View repository
Engineering notes

The controller validates incoming DTOs and passes them to the service. A central exception handler gives failed requests a consistent response.

Spring Data JPA handles persistence. Creation and update timestamps follow each record through its lifetime.
