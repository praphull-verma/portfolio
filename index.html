Project 01Backend / API

ERP Management System

A modular ERP backend with structured routing, middleware, and a schema-driven data layer built on Prisma ORM and PostgreSQL.

  • TypeScript
  • Node.js
  • Express.js
  • Prisma
  • PostgreSQL
  • JWT
  • bcrypt
  1. RequestREST
  2. RouterStructured routes
  3. MiddlewareJWT in HTTP-only cookie
  4. ValidationRequest checks
  5. PrismaSchema-driven
  6. PostgreSQLRelational store
Problem

An ERP handles records many people must not touch freely. Every request has to be identified, authorized and validated before it reaches the data, and that should come from the structure of the code, not from habit.

What I built
  • Authentication and authorization
  • Password hashing with bcrypt
  • JWT authentication using HTTP-only cookies
  • Protected routes and middleware
  • Request validation
  • REST API endpoints
Key engineering decisions
  • The token lives in an HTTP-only cookie, so page scripts cannot read it.
  • Passwords are stored only as bcrypt hashes.
  • Routing, middleware and the Prisma schema stay in separate modules, so each can change on its own.

Project 02Full-stack / Real-time

CampusConnect

A student collaboration platform for finding teammates, creating teams, communicating, and collaborating across campuses.

  • JavaScript
  • Firebase
  • Firestore
  • Supabase
campusconnect.quest
Problem

Students on different campuses rarely have one place to find teammates, form a team and talk. CampusConnect puts discovery, teams and conversation together.

What I built
  • User authentication and profiles
  • Team creation and invitation workflows
  • Real-time messaging
  • Presence tracking
  • Database schema design
  • File sharing
Key engineering decisions
  • Firestore carries the live parts: messaging and presence.
  • Supabase handles shared files, separate from the message store.
  • The schema is planned around users, teams, invitations and messages.
Project 03Backend / REST

Student Management System

A RESTful student management backend using layered architecture and DTO-based request and response models.

  • Java
  • Spring Boot
  • Spring Data JPA
  • MySQL
Problem

Student records need predictable create, read, update and delete behaviour, clear responses when something fails, and no accidental loss of data.

What I built
  • CRUD APIs
  • Input validation
  • Centralized exception handling
  • Soft deletion
  • Automatic creation and update timestamps
Key engineering decisions
  • DTOs sit between the API and the entities, so the database model is not exposed directly.
  • One exception handler gives every error the same shape.
  • Soft deletion keeps records recoverable instead of removing rows.
